# locallm — локальный ИИ для больших книг

Go-модуль для десктопного приложения в стиле Heptabase: загружает книги и документы
(до 1500+ страниц), строит локальный иерархический индекс и отвечает на вопросы **только по
вашим документам** — полностью офлайн, на обычном ноутбуке без GPU (8–16 ГБ RAM).

* **Один файл.** llama.cpp вкомпилирован в бинарник (cgo, статическая линковка, `tcpipuk/llama-go`).
  Нет Ollama, нет `llama-server`, нет HTTP к localhost для генерации. Зависит только от системных `libc`/`libm`.
* **Ничего не настраивать.** Модели вшиваются в тот же файл (`locallm pack`) и при первом запуске
  распаковываются сами. Под объём RAM модель выбирается автоматически.
* **Нет сети.** В программе нет ни одного исходящего запроса. Скачивание моделей — только скрипт сборщика.
* **Русский и английский.** Мультиязычные эмбеддинги + русский стемминг в лексическом поиске.
* **Форматы:** PDF, DOCX, ODT, EPUB, FB2 (в т.ч. windows-1251 и .fb2.zip), RTF, HTML, TXT, Markdown.

## Для пользователя

**Просто запустите `locallm` (двойной щелчок по файлу).** Откроется окно в браузере — локальный интерфейс
в духе Heptabase: бесконечная доска с карточками и связями, чат с книгой справа, оглавление, поиск (Ctrl+K).
Перетащите файл книги в окно — и можно спрашивать. Ничего не уходит в интернет: страница работает только
с вашей программой на 127.0.0.1 (это закреплено политикой безопасности страницы).

* **Доска:** двойной щелчок — новая заметка; колесо мыши — прокрутка, Ctrl+колесо — масштаб; потяните за синюю точку
  у края карточки, чтобы связать её с другой; Delete — удалить выбранное. Доски сохраняются на диск автоматически.
* **Чат:** ответ со ссылками [1], [2] на страницы; кнопка «На доску» кладёт ответ карточкой и связывает с книгой;
  режим «Только поиск» мгновенно показывает места в книге без генерации (удобно на слабом процессоре).
* **Оглавление:** «Кратко» по любому разделу и «Обзор всей книги» — результат появляется карточкой на доске.

Консольный режим:

```
locallm книга.pdf              # открыть книгу и задавать вопросы
locallm ask книга.pdf "О чём глава 3?"
locallm summary <id> 5         # краткое содержание раздела 5 (без номера — всей книги)
locallm doctor                 # диагностика
```
На Windows можно перетащить файл книги на `locallm.exe`.
При первой загрузке книги строится индекс (один раз; потом открывается за доли секунды).
**Отвечать можно сразу**, не дожидаясь векторов: пока они строятся, работает лексический поиск (BM25).

## Для разработчика

На Windows: `powershell -ExecutionPolicy Bypass -File scripts\build-windows.ps1`.
```
make deps      # один раз: собрать llama.cpp (нужны git, cmake, gcc/clang)
make build     # → bin/locallm
make test      # быстрые тесты, llama.cpp не нужен
make test-real # то же на настоящем llama.cpp с крошечными тестовыми моделями
make models && make bundle LLM=models/qwen2.5-3b-instruct-q4_k_m.gguf EMBED=models/Qwen3-Embedding-0.6B-Q8_0.gguf
```
Подробно: [docs/BUILD.md](docs/BUILD.md), [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), [docs/MODELS.md](docs/MODELS.md).

### Встраивание в Go-приложение (Wails)

```go
eng, _ := locallm.Open(locallm.Options{})              // всё подбирается автоматически
book, _ := eng.AddBook(ctx, "/путь/книга.pdf", nil)    // секунды: чтение + дерево глав
go book.Index(ctx, func(p locallm.Progress) { /* прогресс векторов → в UI событием */ })

ans, _ := book.Ask(ctx, locallm.AskRequest{ChatID: "c1", Question: "Кто главный герой?"},
    func(tok string) { /* стриминг в UI */ })
// ans.Sources — страницы и главы, на которые опирается ответ
```
Для не-Go фронтенда: `locallm serve` поднимает API на `127.0.0.1:8787` (токен-аутентификация, проверка Host/Origin);
см. `internal/server`. Это API для UI, к нему не ходит сама генерация.

## Что важно знать (честно)

* **Скорость на CPU.** Генерация 3B-модели Q4 на ноутбуке — порядка 5–12 токенов/с; до первого токена
  проходит время на обработку промпта (по умолчанию ≤ ~2200 токенов фрагментов). Для слабых машин —
  `-profile fast` (1.5B). Окно/объём фрагментов настраиваются (`MaxContextTokens`).
* **Скан-PDF** (картинки без текстового слоя) не поддерживаются: OCR потребовал бы внешней зависимости.
  Программа сообщит об этом явно. Старый бинарный `.doc` тоже не поддерживается (сохраните как DOCX/ODT).
* **Лицензия PDF-движка.** Чтение PDF идёт через `go-fitz` → MuPDF, лицензия **AGPL**. Для закрытого
  коммерческого приложения нужна коммерческая лицензия Artifix или замена PDF-ридера
  (код изолирован в `internal/extract/pdf.go`).
* **GPU** в релизной сборке не используется (кроме Metal на macOS): Vulkan требует системный загрузчик,
  а это нарушило бы «ничего не устанавливать». Опционально — см. docs/BUILD.md.
* Windows-сборка настроена в CI (MSYS2), но в разработке проверялась только Linux — см. docs/BUILD.md.
